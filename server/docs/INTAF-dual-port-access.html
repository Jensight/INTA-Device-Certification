Background

The Rogers Framework Backend runs two servers simultaneously on the same Express app instance:

ServerProtocolPortPurpose
httpServerHTTP8080API plugin calls, vauto-api, test-case execution
httpsServerHTTPS8081Normal Angular UI → Node API calls

Because the two servers use different protocols and ports, any client host that needs to call both must be explicitly whitelisted in three separate security layers.

Backend Changes

1. server/config.js — Port Constants

Defines the two port numbers used throughout the backend. These values are read by server.js to start each server.

module.exports = {
    serverport: 8081,   // HTTPS port — UI to Node API calls
    httpPort:   8080,   // HTTP port  — API plugin / vauto-api / test-case
    httpsPort:  8081,   // HTTPS port — normal UI calls
    ...
};
  • httpPort: 8080 — plain HTTP server port, used by API plugins, vauto-api, and test-case routes.
  • httpsPort: 8081 — TLS-secured server port, used by the Angular UI for all standard API calls.
  • No IP address is hardcoded here; this file solely owns the port values that the rest of the backend references via config.httpPort / config.httpsPort.

2. server/server.js — Dual-Server Startup

Imports both servers from connect.js and binds them to their respective ports.

var server     = conn.SERVER;       // httpsServer — port 8081
var httpServer = conn.HTTP_SERVER;  // httpServer  — port 8080

var httpsPort = config.httpsPort || 8081;
var httpPort  = config.httpPort  || 8080;

const startServer = async () => {
    // HTTPS server — UI to Node API calls
    server.listen(httpsPort, ...);
    // HTTP server — API plugin calls (vauto-api / test-case routes)
    httpServer.listen(httpPort, ...);
};
  • server.listen(httpsPort) — starts the TLS server (httpsServer) on port 8081.
  • httpServer.listen(httpPort) — starts the plain HTTP server on port 8080.
  • Both servers share the same Express app instance (set up in connect.js), so all routes, middleware, and controllers are available on both ports.

3. server/utils/connect.js — Security Whitelisting

The IP address 172.23.234.176 was added as a trusted origin/host across all three security layers:

3a. CORS (app.use(cors(options)))

Controls which browser origins are allowed to make cross-origin HTTP requests to the Express app.

const options = {
  origin: [
    ...
    'http://172.23.234.176:8080',   // ← HTTP / port 8080
    'https://172.23.234.176:8081',  // ← HTTPS / port 8081
    ...
  ],
  credentials: true
}
  • http://172.23.234.176:8080 — allows requests arriving on the HTTP server (port 8080).
  • https://172.23.234.176:8081 — allows requests arriving on the HTTPS server (port 8081).
  • credentials: true — permits cookies and Authorization headers to be sent along with the requests.

Without these entries the browser would block the response with a CORS error before any application logic runs.

3b. Host Validation (app.use(hostValidation(...)))

A secondary server-side guard that validates the Host header of every incoming request. This prevents Host header injection attacks.

app.use(hostValidation({
  hosts: [
    ...
    '172.23.234.176:8080',  // ← HTTP / port 8080
    '172.23.234.176:8081',  // ← HTTPS / port 8081
    ...
  ]
}));
  • Requests whose Host header does not match an entry in this list are rejected with 403 Forbidden before reaching any route handler.
  • Both port entries are needed because the Host header sent by the client includes the port number.

3c. Socket.IO CORS (socketIo(server, { cors: { origin: [...] } }))

Controls which origins are permitted to establish a WebSocket/Socket.IO connection.

const io = socketIo(server, {
  cors: {
    origin: [
      ...
      'http://172.23.234.176:8080',   // ← WS over HTTP / port 8080
      'https://172.23.234.176:8081',  // ← WSS over HTTPS / port 8081
      ...
    ],
    methods: ["GET", "POST"],
    credentials: true
  },
  allowEIO3: true
});
// Socket.IO is also attached to httpServer so it works on port 8080
io.attach(httpServer);
  • The main Socket.IO instance attaches to httpsServer (port 8081).
  • io.attach(httpServer) attaches the same io instance to httpServer (port 8080) as well, so real-time events work regardless of which port the client connects through.

UI Changes

4. src/environments/environment.prod.ts — Production URL Config

This is the Angular production environment config. It tells the UI which backend base URLs to call.

export const environment = {
  ...
  SERVER:      'https://172.23.234.176:8081/',  // HTTPS — normal UI → Node API calls
  SERVER_HTTP: 'http://172.23.234.176:8080/',   // HTTP  — API plugin / vauto-api / test-case calls
  ...
};
  • SERVER (8081) — used by all standard Angular HTTP service calls that go through the HTTPS server.
  • SERVER_HTTP (8080) — used specifically for API-plugin, vauto-api, and test-case execution calls that must go through the plain HTTP server.

All Angular services that inject the environment URLs automatically target 172.23.234.176 when the app is built with --configuration production.

5. src/app/models/config.ts — Central URL Exports

This is the single file all Angular services import to get the backend base URL. It reads from the environment so there is no URL hardcoded anywhere in the services themselves.

import { environment } from '../../environments/environment';
export const SERVER      = environment.SERVER;       // HTTPS — normal UI to Node API calls
export const SERVER_HTTP = environment.SERVER_HTTP;  // HTTP  — API plugin / vauto-api / test-case
export const ENABLE_SSO  = environment.ENABLE_SSO;
  • SERVER resolves to https://172.23.234.176:8081/ in production builds.
  • SERVER_HTTP resolves to http://172.23.234.176:8080/ in production builds.
  • In development builds (environment.ts) both resolve to http://localhost:8080/, so dev behaviour is unchanged.
  • No change was required to the services or components that import { SERVER, SERVER_HTTP } from '../models/config' — the URL flows through automatically.
